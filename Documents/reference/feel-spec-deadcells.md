# 手感规格（Feel Spec）— Dead Cells 风格样例

> **数据可信度声明（重要，先读）**
>
> Dead Cells 的官方手感参数**从未公开** —— Motion Twin 没有发布过 frame data 或
> 数值表。下表的来源分三类，已逐行标注：
>
> - `[社区]` = 社区公认 / 多来源一致的经验值（如土狼时间 0.10s）
> - `[推导]` = 用跳跃高度 3 格、滞空 0.75s 反推的物理量，内部自洽
> - `[推断]` = 按实际观感估的经验值，**不是官方数据**
>
> 把这些数字当成**"能复现 Dead Cells 手感"的起点**，而不是官方真相。
> 真正的流程是：先照抄，再靠调参面板调到你自己觉得对。

## 换算基准

| 项 | 值 |
|---|---|
| 画面基准分辨率 | 480×270（16:9，整数缩放到 1920×1080 = 4×） |
| 1 格（Tile） | 16 px |
| 玩家碰撞盒 | 约 12 × 22 px |
| 目标帧率 | 60 FPS（所有帧数按 60 FPS 计） |

**关键换算**：3 格 = 48 px，滞空 0.75s，反推得

```
设总滞空 t = 0.75 s（上升 0.375 + 下落 0.375），高度 h = 48 px：

  上升时间 t_up = t/2 = 0.375 s
  跳跃初速 v0 = g·t_up，且 h = v0²/(2g)  ⟹  v0 = 4h/t = 4×48/0.75 = 256 px/s
  重力     g  = 8h/t²                  = 8×48/0.75² = 682.7 px/s²
```

> ⚠️ **勘误（已修正）**：本文早期版本写作 `v0 = 2h/t = 128`，**漏了因子 2**，
> 会得到 12px 高度、0.375s 滞空（仅为目标的 1/4 与 1/2）。
> 正确公式是 **v0 = 4h/t**（等价于 g·t/2）。重力 682.7 本身是对的。

Godot 里直接用 `256.0` 和 `682.7` 这两个数即可（记得把角色场景缩放设成整数倍）。

**自洽校验**（改任何一个参数后都应满足）：

```
h = v0²/(2g) = 256² / (2×682.7) = 48.0 px  ✓
t = 2·v0/g   = 2×256 / 682.7    = 0.75 s   ✓
```

## 取消规则（Canceling）— 这里有个**重大修正**

模板里假设"攻击后摇可被冲刺取消"。**但 Dead Cells 实际不是这样设计的**，
这也是它和很多"手感爽"的横板游戏最本质的区别：

### Dead Cells 的真实做法

```
- 攻击后摇可被 → 冲刺 取消？          ❌ 不能
- 攻击后摇可被 → 跳跃 取消？          ❌ 不能
- 攻击后摇可被 → 下一次攻击 取消？    ✅ 能（连击链，且只能往后接）
- 跳跃可被 → 攻击 取消？              ❌ 不能（空中可攻击，但不取消跳跃）
- 受击硬直可被输入打断？              ❌ 完全不能
- 滚动可被 → 攻击 取消？              ✅ 能（后摇第 4 帧起）
- 滚动可被 → 跳跃 取消？              ✅ 能（后摇第 4 帧起）
```

### 但它的手感为什么照样爽？靠的是「输入缓冲」而非「取消」

```
按下必杀/跳跃的输入 → 进入缓冲队列（6 帧）→ 后摇结束瞬间立即释放
```

**这是关键设计洞察：**

| 方案 | 后果 |
|---|---|
| **取消（Cancel）** | 你能提前打断动画 → 手感"顺滑"，但**攻击失去重量**，玩家可以无脑连点 |
| **缓冲（Buffer）** | 动画必须播完 → 每一下都有承诺，**但玩家不觉得"输入丢了"** |

Dead Cells 选的是**缓冲**。攻击后摇的 8 帧是你为这次挥砍付出的**真实代价**，
而 6 帧输入缓冲保证你下一次操作不会因为"手快了 0.05 秒"而失效。

**结论：不要为了"手感顺"而给攻击加取消窗口。** 那会让横板动作变成无脑连点。
正确的顺序是：

1. 先做**输入缓冲**（必须，这是"不丢输入"的保障）
2. 再做**后摇时长微调**（调短到你觉得"有重量但不烦"）
3. **最后才考虑**给特定武器加取消（作为武器特性，而不是全局规则）

## 三个「一秒就能感觉到」的调参杠杆

如果只能改三个参数，改这三个，按收益排序：

| 杠杆 | 怎么调 | 效果 |
|---|---|---|
| **1. 顿帧** | 命中 0 → 5 帧 | 打击感从"切纸"变"砍骨头"，**收益最大，成本最低** |
| **2. 转身加速度** | 提到 2200+ | 转身干脆度 = 操作响应感。很多游戏手感"黏"就是这里太低 |
| **3. 土狼时间 + 跳跃缓冲** | 各给到 6 帧 | 从"这游戏跳跃有病"变"很跟手"，玩家说不出原因但能感觉到 |

**反面杠杆**：把加速度设成无限大（瞬间到全速）会**破坏**手感 —— 这是新手最常见的错误。
保留 0.1s 的加速过程，是"有重量"的来源。

## 这套数字和 Dead Cells 的差异（诚实说明）

| 项 | 说明 |
|---|---|
| **不是官方数据** | Motion Twin 未公开 frame data，上表是反推 + 校准 |
| **跳跃偏矮** | Dead Cells 跳跃只有 3 格，主要靠**滚动**做位移。如果你的游戏跳跃是主位移手段，高度要加大到 4–5 格 |
| **无二段跳** | Dead Cells 无二段跳，但有"贴墙跳"和"蜘蛛符文"爬墙 |
| **滚动是核心** | 它的位移、无敌、取消全靠滚动。你的游戏若不想要滚动，需要另找无敌帧载体（如冲刺） |
| **武器差异极大** | 上表是"平均武器"。Dead Cells 里匕首 3 帧前摇、大剑 12 帧前摇，**数值随武器浮动** |

## 落地到 Godot 的建议

**1. 第一时间做调参面板。** 上面 30 多个参数如果硬编码，你每调一次都要重编译，
调手感会变成折磨。建议：

```gdscript
# feel_config.gd — 挂到一个 Resource 上，可在 Inspector 实时改
class_name FeelConfig
extends Resource

@export var gravity: float = 682.7
@export var max_fall_speed: float = 700.0
@export var jump_velocity: float = 256.0
@export var coyote_time: float = 0.10
@export var jump_buffer_time: float = 0.10
@export var max_run_speed: float = 165.0
@export var accel: float = 1650.0
@export var decel: float = 1150.0
@export var turn_accel: float = 2200.0
@export var hit_stop_hit: int = 5      # 帧
@export var hit_stop_kill: int = 10    # 帧
@export var shake_hit: float = 2.0     # px
@export var shake_kill: float = 4.0    # px
```

跑游戏时改 Inspector 里的值会**立即生效**（Godot 的 `@export` 在调试运行中可实时编辑）。

**2. 输入缓冲必须先写。** 在玩家状态机里维护一个计时器：

```gdscript
var _jump_buffer_timer := 0.0

func _process(delta: float) -> void:
    if Input.is_action_just_pressed("jump"):
        _jump_buffer_timer = feel.jump_buffer_time
    else:
        _jump_buffer_timer = maxf(0.0, _jump_buffer_timer - delta)

func _physics_process(delta: float) -> void:
    var on_floor := is_on_floor()
    if on_floor:
        _coyote_timer = feel.coyote_time
    else:
        _coyote_timer = maxf(0.0, _coyote_timer - delta)

    # 有缓冲 且 在土狼窗口内 → 起跳
    if _jump_buffer_timer > 0.0 and _coyote_timer > 0.0:
        velocity.y = -feel.jump_velocity
        _jump_buffer_timer = 0.0
        _coyote_timer = 0.0
```

**3. 顿帧不要用 `Engine.time_scale`。** 全局减速会连 UI 和音效一起拖慢。
正确做法是只冻结实体逻辑：

```gdscript
func apply_hit_stop(frames: int) -> void:
    _hit_stop_frames = frames

func _physics_process(delta: float) -> void:
    if _hit_stop_frames > 0:
        _hit_stop_frames -= 1
        return   # 跳过本帧逻辑，但动画/粒子/UI 照常
```

## 待你填的空

| 问题 | 你的答案 |
|---|---|
| 跳跃是主位移手段还是辅助？ | → 决定跳跃高度（3 格？5 格？） |
| 无敌帧挂在滚动、冲刺、还是格挡上？ | → 决定整套防御循环 |
| 受击无敌 1.0s 是否太长？ | → 若你的敌人更密集，降到 0.6–0.8s |
| 是否要保留滚动？ | → 不要的话，"转身加速度"和"缓冲"的重要性各加一档 |
| 武器数值是否差异化？ | → 是的话，上面攻击帧数要拆成每武器一份 Resource |
