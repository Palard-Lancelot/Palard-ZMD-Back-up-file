## 1. 设计支柱（Design Pillars）⭐ 核心中的核心

**定义：3 条不可妥协的原则。** 任何新功能、新美术、新道具，如果违反其中任何一条，就砍掉。

每根支柱必须包含：**名称 + 一句话主张 + 它禁止了什么**。

### 支柱 1：每一击都有反馈
- **主张**：敌我双方的每一次攻击都产生可感知的效果，无论伤害大小。
- **玩家能感知到的表现**：顿帧、屏震、受击闪白、击退、音效。
- **它禁止了什么**：禁止任何"瞬发且无反馈"的伤害与效果。
- **如何验证**：逐帧检查每次命中是否触发顿帧 + 音效 + 受击方闪白。

### 支柱 2：持之以恒的训练肯定有效果
- **主张**：玩家随手法熟练必然能实现无伤通关。
- **玩家能感知到的表现**：手部乘区（技巧）对结果的影响，绝不少于运气带来的装备影响。
- **它禁止了什么**：禁止"无效死亡"—— 即任何无法通过技巧规避的伤害。
- **如何验证**：高手可稳定无伤通关；不存在无预警伤害。

### 支柱 3：Build 决定打法，而非数值
- **主张**：道具改变的是玩法方式，不是数字大小。
- **玩家能感知到的表现**：高收益必然伴随高风险；不同 Build 需要不同打法。
- **它禁止了什么**：禁止纯数值堆砌的道具设计（如"+10% 攻击力"）。
- **如何验证**：任意两件道具对比，是否导致**操作方式**改变而非仅数值变化。

> **支柱自检**：把一根支柱的"禁止项"划掉，它还站得住吗？站得住 → 它是愿望，不是支柱。

---

### 设计约束（非玩法主张，但同样不可违反）

### 约束 A：遵循原著
- **内容**：剧情、美术、战斗等系统不得脱离《终末地》原有设定。
- **玩家能感知到的表现**：终末地由 3D 变为 2D 横板肉鸽，但世界观与设定一脉相承。
- **它禁止了什么**：禁止脱离原著自创核心设定。
- **如何验证**：每一项设定回到原著中找依据。

> ⚠️ **约束，而非支柱**：它是"内容来源的限制"，不是"玩法为什么好玩"。
> 因此与上述 3 条玩法支柱分开列出。

> ✅ **IP 处置已定案（非 IP 化运营）**：
> - 本项目**不做商业化发行**，不涉及 IP 授权、不涉及变现
> - 定位为**同人性质的练习 / 作品集项目**
> - 因此**不需要**为了发行而做设定替换
> - ⚠️ 但**发布渠道仍需注明为同人作品**（如 itch.io 免费发布时标注 fan project）
> - 📌 **保留做法**：地名、物种名仍建议抽成**数据表**（见第 7.4 节），
>   理由不是"为了换皮"，而是**为了满足"随原著更新加地图"的可发展性要求**

> ⚠️ **风险提示**：即便非商业，公开传播同人作品在极端情况下仍可能被要求下架。
> 缓解措施：**不商业化、不收费、明确标注同人属性**，可显著降低该风险。

## 2. 核心循环（Core Loop）

按"秒 → 分 → 局 → 跨局"四层各写一遍，每层都要有**明确的决策点**（没有决策的循环不是游戏）。

| 层级 | 时长 | 循环内容 | 玩家在此做的**决策** | 反馈/奖励 |
|---|---|---|---|---|
| 微循环 | 1–5 秒 | 观察 → 位移/闪避 → 攻击 → 重置 | ① 贴脸还是拉开 ② 何时闪避 ③ 攻击后摇要不要用冲刺取消 | 命中帧 + 顿帧、伤害数字、音效、粒子、残影、无敌帧白闪 |
| 房间循环 | 30–90 秒 | 进入房间 → 清怪 / 绕过 → 探索分支 → 决定去留 | ① 清怪还是绕过 ② 开不开带风险的宝箱 ③ **进这个房间还是回退走别的路** ④ 道具与现有 Build 的联动取舍 | 门开动画、光柱、三选一 + 稀有度光效、地图揭示、金币结算 |
| **单层探索循环**（新增层） | **5–12 分钟** | 探索本层连通图 → 找出口 / 清可选房 → **回退补漏** → 离开本层 | ① **先探哪条分支**（层内多入口，可回头）② 是否绕回去开之前放弃的宝箱 ③ **何时认定"这层搜完了"** ④ 出口选择（安全路 vs 高收益路） | 本层地图完成度、捷径解锁、门开动画 |
| 单局循环 | **60–90 分钟** | 开局 → **逐层推进（每层内连通探索）** → 精英/事件 → Boss → 死/通关 | ① 走哪条路（层间分叉图）② 资源投"永久强化"还是"本局消耗品" ③ 血量健康时：贪一层还是稳一手 ④ Boss 前：花光资源还是留作复活 | 构筑可视化、角色道具与技能的增加、新区域/新敌人、通关/重开 |
| 元循环 | 数小时 | 死亡 → 结算魂/解锁 → 选永久强化 → 再开一局 | ① 永久解锁的武器图纸 ② 换不换初始武器 ③ 追不追某个成就/挑战（每日种子） ④ 今天继续还是收手（新鲜感） | 天赋树点亮、解锁新道具池、图鉴填充、隐藏内容 |

**循环自检**：
- [ ] 微循环在没有奖励的情况下，单纯操作是否也爽？（动作游戏必须"是"）
- [ ] 房间循环是否每 2 分钟就给一次有意义的抉择？
- [ ] **单层内的"回退"是否有意义？**（必须是"发现漏了东西才回去"，不能是迷路乱转）
- [ ] 单局循环是否每 2 分钟就给一次有意义的抉择？
- [ ] 元循环是否让"失败的一局"依然推进了某样东西？

> 📐 **结构定义（v1.2 关键）**：
> ```
> 层 1（连通图，可回退）─→ 出口 ─┐
>                                 │ 单向，不可回退
> 层 2（连通图，可回退）─→ 出口 ─┤
>                                 │
> 层 3（连通图，可回退）─→ Boss ─┘
> ```
> **层内**：多入口、可回头、有可选房 → 探索感
> **层间**：选定出口即推进，不能返回上一层 → 保留 Dead Cells 的推进压力

## 3. 玩家体验目标（Experience Goals）

| 我们想让玩家感到 | 用什么机制制造 | 反面：我们不想让玩家感到 |
|---|---|---|
| **自由探索当前地图** | ① **每层内是一张连通图**，可自由回退到本层已探索区域 ② 可选路径：宝箱房 / 商店 / 隐藏房间不强制进入 ③ 地图逐步揭示，未探索区域有视觉标记 ④ **无时间压力惩罚** ⑤ "还有东西没拿"的诱因（未开宝箱图标） ⑥ 层内捷径，缩短回退路程 | **强制线性推进** —— 走廊式单行道，玩家没得选 |
| 紧张但可控 | 血量低但闪避无消耗 | 被围殴无处可逃 |
| 每一步都算数 | 房间决策直接改变本局构筑 | 打半天没有实质变化 |
| **搜干净的安全感** | 层内可回退 → 玩家能确认"这层没有遗漏"再走 | 错过东西却无法回头，事后懊悔 |
| | | |

> ✅ **已定案（v1.2）**：探索范围为 **"层内连通可回退，层间单向推进"**。
> - **层内**自由探索（多入口、可回头、可选房）→ 制造探索感
> - **层间**单向推进（选定出口即离开，不能返回）→ 保留 Dead Cells 的推进压力与节奏
>
> **连带影响**（较轻，非结构性重写）：
> - 单局时长 20–40 → **60–90 分钟**（见第 0、2 节）
> - 第 5 节新增**层内连通性**校验约束
> - 第 4 节新增**单层连通图生成**与**地图系统**
> - 第 7 节工时小幅增加（见第 7.6 节）

## 5. 随机性设计（肉鸽的命门）

| 问题 | 回答 |
|---|---|
| 什么是**随机**的？ | 房间排列（节点用哪个预制块）、**每层连通图的拓扑结构**、道具掉落、敌人配置、**竖井洞口位置**、**竖井台阶形态**（级数 / 级距 / 宽度 / 水平错位）、**房间内部层次**（平台与夹层的数量/位置），均在可通行约束内随机 |
| 什么是**固定**的？ | 可操作角色（**始终为管理员**）、初始道具、**层的数量与推进顺序**、最终 Boss、初始装备、所有预制房间本身 |
| 随机是**均匀**还是**加权**？ | 加权 + 校验重试。加权维度：生物群系主题、房间类型配额、敌人出现约束、**可选房占比**；不通过就重抽 |
| 有没有**保底机制**？ | ① 校验重试保证布局合法 **② 层内连通性检查保证不迷路** ③ 战利品等级跟随生物群系 ④ 逆风时提升经济收益 |
| 有没有**反重复**？ | 有。允许重复道具，靠等级区分；房间层面靠"最近用过的块进冷却池" |
| 随机种子是否存档？ | 是 |
| 最坏情况一局会烂成什么样？ | 生成出**连通但回退体验差**的层（比如出口在图的另一端，迫使长距离折返）。校验重试**无法完全避免**，需靠捷径约束（C 类约束 13）缓解 |
| **技巧 vs 运气**的权重比 | **7 : 3** |

**约束条件**（生成器必须满足的硬规则，逐条写清）：

**A 类 —— 层内连通性（v1.2 新增，本层结构的地基）**
1. **本层连通**：每层内部任意两个房间之间必须互通（从任何房间都能走回本层出口）
2. **可通关**：本层入口 → 本层出口（或 Boss 房）必有路径
3. **回退路径存在**：任何单向跌落/跳下点，必须有可返回的路线
   （或明确标记为"有去无回"的捷径）
4. **无孤立区域**：不允许生成玩家永远到不了的房间（浪费内容且破坏地图完成度）
5. **出口可达性**：本层出口**不应**需要"探索完所有房间"才能到达
   （否则变成清图，失去"可选探索"的自由感）

**B 类 —— 节奏与内容分布**
6. 每个战斗块有敌人数量配额，不能随机撒怪
7. 每层有固定数量的宝箱房 + 商店
8. 原型图控制特殊房间数量
9. 房间必须符合生物群系主题
10. 敌人有空间/组合约束（大体积敌人不能在窄房、某些敌人不可同平台）
11. 特殊房间沿路径分布，不聚堆

**C 类 —— 层内探索节奏（v1.2 新增）**
12. **地图规模上限**：每层房间总数受控（建议 12–20 间），
    否则单局 60–90 分钟会失控
13. **捷径设计**：层内至少生成 1–2 条缩短回退路程的捷径
    （否则"回退"变成折返跑 —— 这是层内连通最大的体验杀手）
14. **可选房占比**：可选房间（宝箱/商店/隐藏）应占本层 30–50%，
    保证"探索有收益，但不探索也不卡关"

> 📌 **比原设计增加的难度**：本层的"层内连通 + 可回退 + 捷径"比
> 原来"单向推进"的生成难度高，但**远低于银河城的整局连通 + 门控可解性**
> —— 不需要图论级可解性校验，只需**单层连通性检查**（并查集即可）。
> 工时影响见第 7.6 节。

## 6. 手感规格（Feel Spec）—— 横板动作游戏的生死线

**把这些数值先定一个"感觉对"的初始值，然后在游戏内做成可实时调节的参数。**

| 参数 | 初始值 | 说明 |
|---|---|---|
| 重力 | 682.7 px/s² | 反推自 3 格 / 0.75 s |
| 最大下落速度 | 700 px/s | 约 8–9 格/s |
| 跳跃高度 | 48 px（3 格） | |
| 滞空时间 | 0.75 s | 上升 0.375 s + 下落 0.375 s |
| 土狼时间（Coyote Time） | 0.10 s（6 帧） | 离台后仍可跳 |
| 跳跃缓冲（Jump Buffer） | 0.10 s（6 帧） | 落地前按跳会被记住 |
| 最大水平速度 | 165 px/s | 约 10 格/s |
| 移动加速度 | 1650 px/s² | = 10× 最大速度 → 0.1 s 到全速 |
| 减速度（松手） | 1150 px/s² | 约 0.14 s 停下，有轻微滑行 |
| 转身加速度 | 2200 px/s² | 比起步更快，招牌手感 |
| 空中操控 | 0.75× | 空中加速略弱但仍有控制 |
| 攻击前摇 | 4 帧 | 起手几乎无延迟 |
| 有效帧 | 3 帧 | 判定窗口窄 |
| 攻击后摇 | 8 帧 | |
| 无敌总时长 | 21 帧（0.35 s） | 冲刺全程无敌 |
| 无敌起始/结束 | 第 3 / 第 20 帧 | 两端都不是无敌 |
| 起身脆弱帧 | 后摇 6 帧 | 风险所在 |
| 受击无敌帧 | 60 帧（1.0 s） | 相当长 |
| 受击击退 | 24 px（1.5 格） | 水平为主 |
| 受击硬直 | 12 帧（0.2 s） | 不可操作 |
| 顿帧（Hit Stop） | 命中 5 帧 / 击杀 10 帧 | 打击感第一功臣 |
| 屏震幅度 | 2 / 4 / 8 px | 小幅度高频 |
| 屏震时长 | 4–6 帧快速衰减 | 必须比顿帧先结束 |
| 输入延迟上限 | < 50 ms | 关 V-Sync |

**取消规则（Canceling）—— 手感高级感几乎全在这里：**

| 取消方向 | 是否可取消 | 说明 |
|---|---|---|
| 攻击后摇 → 冲刺 | ✅ **能** | **有意偏离 Dead Cells（原作不能）** |
| 攻击后摇 → 跳跃 | ✅ **能** | 同上 |
| 攻击后摇 → 下一次攻击 | ✅ 能 | 连击链，只能往后接 |
| 受击硬直被输入打断 | ❌ 完全不能 | 受击即失去控制权 |
| 冲刺后摇 → 攻击 / 跳跃 | ✅ 能 | 第 4 帧起 |

> ⚠️ **设计说明（有意偏离）**：Dead Cells 实际**不提供**攻击后摇的冲刺/跳跃取消，
> 它靠"输入缓冲"（6 帧队列）实现流畅感，以此保住每一击的重量。
> 本项目选择**提供取消**，换取更爽快的动作节奏 ——
> 代价是攻击的"承诺感"降低，需靠**顿帧与后摇长度**补回重量感。
> 这与支柱1「每一击都有反馈」存在张力，**属已知取舍**。

### 单向平台下穿（v1.3 新增）

| 项 | 规格 |
|---|---|
| 键位 | **`S` + `Space`**（`S` 按住的状态下按跳跃键，同一帧判定） |
| 生效对象 | **仅 `one_way_collision` 的平台**（竖井攀爬台阶）；实心地 / 墙**不生效** |
| 生效条件 | 站在平台上；冲刺 / 受击硬直 / 死亡期间**不可** |
| 忽略窗口 | 下穿后 **15 帧（0.25 s）** 内忽略该平台碰撞，随后自动恢复 |
| 代价 | 下穿**不给**上升速度，也**不消耗**任何资源 —— 这是"落下"，不是"跳" |

> **为什么需要**：竖井台阶必须是单向平台（从下方可穿过、从上方可站立），
> 否则玩家从下往上跳会撞头。但单向平台反过来造成"上得去、下不来"——
> 玩家上了高台只能原路跳到边缘再落，回退体验从"走"退化成"绕"。
> 下穿把这个空洞补上，也让「层内可回退」在竖井里真正成立。

> **不做的部分**：不做"按住 S 持续下落穿过多层"（Dead Cells 的快速下坠）。
> 那会引入新的速度/无敌/受击规则，属于阶段 1 之后的移动拓展。

> **键位修订记录**：初版规格写的是 `W` + `Space`，实机试玩后改为 **`S` + `Space`** ——
> 「向下」用 S 与方向键语义一致（`W` 是上），玩家不会按反。

### 关卡几何：从「规整盒子」到「有机空间」（v1.4）

| 项 | 决定 |
|---|---|
| 背景 | **整层一张连续底板**，不再按房间画矩形色块（色块是"方块感"的视觉来源） |
| 房间类型 | 用**地面色带**表达（宝箱=暖黄 / 商店=紫 / 战斗=冷灰 …），不做整间上色 |
| 房间内部 | 每间房 1–3 块**单向平台**（离地 40–150 px）+ 战斗/精英房 50% 概率一块**实心夹层**（离地 ≥72 px、离侧墙 ≥90 px） |
| 硬约束 | 所有内部结构必须避开竖井通道（上/下行洞 x ± 45 px），否则会堵死攀爬 |
| 尚未做 | **预制房间块**（Dead Cells 真正的做法）：15 块手工模板 + 门洞对齐 → 阶段 1 任务（7.2 已列），本轮不假装完成 |

### 攀爬结构：斜向阶梯（v1.5，对标手写层）

> 手写层的阶梯实测：PlatformA(120,−40) → B(230,−76) → C(340,−108) ——
> **每级抬 34–36px、横向拉开 110px、台宽 48–64**。v1.4 前生成的是"洞里 6–8 级密堆竖梯"，
> 观感与手感都和手写层差得远，v1.5 按手写层的几何重做。

| 项 | 规格 |
|---|---|
| 结构 | 房间内 **4 级斜向阶梯** + 洞内 **1 块发射台**；阶梯在「洞正下方 / 洞旁 dx」两列间交替，视觉上是斜的 |
| 每级 | 抬升 ≈36px（与手写层一致）；横移 dx = 104–122px；台宽 48–64 |
| 发射台 | 洞内、`TOP_LEDGE_Y = 18`（v1.3–v1.4 是 23） |
| 出洞余量 | `29 − TOP_LEDGE_Y` = **11px**（23 时只有 6px，出洞后横向预算 33px < 需要的 24px + 安全量，实测会掉回洞里） |
| 硬约束 1 | **最高一级阶梯必须在洞列**：若在洞旁，玩家往上跳时头顶会撞上层房间的**地板底面**（那里没洞） |
| 硬约束 2 | 台间**边缘**距必须在 40–95px：<40 会撞下一级台子底面（30px 时只升 35px），>80 滞空不够 |
| 验证 | `test_vertical_climb` 改为**逐跳验证**（地面→4 级→发射台→上层房间，共 6 跳 × 每组）；判据仍是"站住" |

### 7.4 可发展性设计（"随终末地更新加地图"的技术前提）

要做到"**新地图 = 加数据，不改代码**"，架构必须从一开始就满足：

| 要求 | 具体做法 |
|---|---|
| **纯数据驱动** | 敌人 / 道具 / 房间 / 大区全部用 `.tres` 资源描述，不写死在代码里 |
| **大区 = 配置集** | 一个新 Biome = 1 个配置目录（主题色板 + TileSet + 敌人表 + 房间池） |
| **共享骨架层** | 通用地形 / 房间 / 敌人行为做底层，各大区只写"增量差异" |
| **生成器参数化** | 关卡长度、特殊房数、敌人配额全部从 Biome 配置读取 |
| **内容注册表** | 新资源丢进目录即被自动扫描加载，不改任何 if / else |

> ⚠️ **反面案例**：如果大区切换靠代码里的 `match biome_id:`，
> 那么每加一个大区都要改代码并**重新测试所有旧大区** —— **可发展性归零**。
> 这是本项目最重要的架构约束。

> - 不需要"钥匙 / 能力门控系统"（省 2.5 周）

## 9. 失败与惩罚设计

| 问题 | 回答 |
|---|---|
| 死亡后**丢失**什么？ | ① **当局收获的金币**（局内货币，全部消失）② **当局内的道具与技能强化** ③ 本局推进的所有层数进度（回到起点） |
| 死亡后**保留**什么？ | ① **元进度货币**（跨局保存，用于永久解锁）② **已解锁的图纸**（决定掉落池内容）③ **玩家自身的知识** —— 敌人前摇、Boss 招式规律、地图结构 |

> ⚠️ **精确定义（重要，易混淆）**：局内获得的道具**进入掉落池，而非永久持有**。
> 死亡后：**道具本身消失**，但它对应的**图纸被永久记录**，从此进入后续局的可掉落池。
> 即：**解锁改变的是"池子里有什么"，不是"你手里有什么"。**

### 9.1 掉落池机制（本设计的核心）

| 层 | 内容 | 死亡后 |
|---|---|---|
| **道具实例** | 本局捡到的那把剑（含等级、词缀） | ❌ **消失** |
| **图纸 / 池** | "该武器已解锁"这条记录 | ✅ **永久保留** |

**运作方式**：

```
本局捡到 → 解锁图纸（池 +1）
         ↓
下一局     → 从「池」里随机抽取本局可掉落的道具
         ↓
每次捡到的道具都是新实例（新的等级 / 词缀）
```

**设计后果（为什么这样设计是对的）**：

| 后果 | 说明 |
|---|---|
| ✅ **池子随游玩变大** | 越玩可遇到的组合越多 → 直接支撑"第 100 局还有感" |
| ✅ **每局重新构筑** | 不能靠"永久持有最强装备"躺赢 → 保住肉鸽核心 |
| ✅ **不破坏支柱3** | 道具不是永久资产，所以每局都要重新做 Build 决策 |
| ⚠️ **副作用：池子会被稀释** | 解锁过多时，想拿到特定道具的概率下降（Dead Cells 也有此问题） |

**对副作用的缓解**（三选一或组合使用）：

| 方案 | 做法 |
|---|---|
| **分类抽取** | 先抽"类别"（近战/远程/技能），再在类别内抽具体道具 |
| **权重机制** | 高频道具权重低，稀有道具权重高；可加"最近未出现"加权 |
| **保底** | 每 N 次三选一必出 1 个"未解锁/新解锁"道具，让池子扩大有正反馈 |
| 是否存在"必死局面"？如何避免？ | **设计上不存在**。四条保证：<br>① 生成器**校验重试**保证起点→Boss 房必有通路（约束1）<br>② 每层至少 2 个道具选择点，不出现资源断崖<br>③ 战利品等级**跟随生物群系**而非玩家，避免推进过快导致装备落后<br>④ **所有伤害都有清晰前摇**，可被闪避/预判——这是支柱2 的硬保证 |
| 玩家能否主动放弃本局？ | **能**。直接退出即视为放弃，失去当局金币与进度。<br>保留元进度（与死亡规则一致，不做额外惩罚） |
| 恶意/自杀式玩法是否会被奖励？ | **不会被奖励，无需专门堵**。理由：<br>① 死亡失去全部当局金币，自杀是纯亏损<br>② 元进度货币按当局推进深度结算，自杀拿不到<br>③ 不设计"死亡换资源"类机制 |
| 失败一局后玩家的情绪应该是？ | **"我知道哪里出错了" + "下次能做得更好"**，而不是"无力"或"被骗"。<br>关键支撑：敌人前摇清晰、Boss 招式固定可背、伤害来源可追溯（受击方向提示） |

**与支柱2 的一致性检查**：⚠️ **需重新审视（v1.2 银河城结构带来的新张力）**。

支柱2 主张"持之以恒的训练肯定有效果"，禁止"无效死亡"。本设计的三重保障：

| 保障 | 作用 |
|---|---|
| 损失只限**当局** | 训练获得的知识与解锁**永久保留**，所以"练了不会白练" |
| 伤害**全部可规避** | 有前摇、有预警 → 死亡永远可归因于操作，而非运气 |
| Boss **招式固定** | 可背版、可学习 → 技巧成长有明确回报 |

> ⚠️ **v1.2 张力提示**：
> 单局从 20–40 分钟拉长到 **60–90 分钟**后，"死亡丢失全部当局进度"的惩罚**变重了**。
> 但**结构仍与 Dead Cells 一致**（分层推进、死亡回起点），所以**规则本身不需要改**。
>
> **需要注意的点**：
> - 60–90 分钟单局 + 清空进度，挫败感高于 20–40 分钟
> - 缓解手段（**不改规则，改体验**）：
>   ① **层内捷径**（约束 C-13）缩短重跑路程
>   ② 元进度解锁**跳过已通关前期层**的能力（Dead Cells 的"符文/捷径"思路）
>   ③ 受击无敌 1.0 s 已较长，可保证不连续掉血
>
> 📌 **Dead Cells 参考依然成立**：它单局也可达 45–60 分钟，死亡同样清空，
> 靠的是"每层很短 + 捷径解锁"来降低重跑痛苦。本作**沿用同一套缓解思路即可**。

> ✅ **已定案**：局内解锁的道具**计入掉落池，而非永久持有**（参照 Dead Cells）。
> 见上方 9.1 节。

> 📌 **本游戏暂无**：Dead Cells 的"诅咒"（开箱受诅、再受伤即死）与"伤势/Malaise"
> （受击累加惩罚）机制。是否需要，见第 12 节。

## 10. 成功标准（Definition of Success）

**用可测的方式写，不要写"好玩"。**

项目性质为**可展示项目（作品集）**，因此验收分两类：**过程验收**（防烂尾）与**成果验收**（作品集价值）。

### 10.1 过程验收（每个阶段必须通过）

| 节点 | 通过标准（可证伪） |
|---|---|
| **阶段 0**（约 2 个月） | 连续玩 5 分钟，**单纯操作本身**让人想继续动；不需任何奖励 |
| **阶段 0**（约 5 个月） | 完成"打怪 → 被打死 → 重开"闭环；给 3 个人试玩，**≥2 人主动再玩一局** |
| **阶段 1**（约 17 个月） | 能完整通关 1 大区；连续 20 局不出现完全相同的构筑组合 |
| **阶段 1** | 盲测玩家能主动说出"打击感好"，而非"还行 / 一般" |
| **阶段 2**（约 20 个月） | 陌生人**不看说明**能自己装上并玩通（说明 UI 与引导合格） |
| 手感验收（全程） | 调参面板可实时改 20+ 参数，不需重新编译 |

### 10.2 成果验收（作品集价值）

| 标准 | 通过判据 |
|---|---|
| **做完了** | 有可下载 Demo + 源码仓库 + README（含 GIF 演示）；**无致命 bug** |
| **有技术深度** | 关卡生成器（校验重试算法）能**独立讲解** ≥15 分钟，并配一篇技术文章 |
| **有完成度** | 标题 / 设置 / 结算 / 音量等**周边功能齐全**，不是"半成品感" |
| **有可发展性** | 新增 1 个房间模板**只改数据文件**，不动代码（可现场演示） |

> ⚠️ **不设"留存率""首局时长"类指标**。那是商业游戏的验收口径，
> 单人作品集项目**没有用户量支撑**，统计没有意义。**以"能展示"替代"能赚钱"。**

### 10.3 止损与复盘判据

工期不限，**因此不能用"截止日期"做止损**。改为**一致性判据**：

| 触发条件 | 动作 |
|---|---|
| 阶段 0 超过 **3 个月**仍未达到"手感可玩" | **停下加内容，只调手感**（说明战斗系统有问题） |
| 连续 **3 周**没有任何 commit | 复盘：是课业压力（可接受）还是动力丧失（需调整范围） |
| 某系统预估工时**超支 3 倍**仍无进展 | 换实现方案，不硬扛 |
| 阶段 1 超过 **24 个月**仍未收口 | **强制定为阶段 2**，先发布现有内容 |

> 📌 **最重要的一条**：本项目的头号风险不是"做不完"，而是**中途放弃**。
> 因此**任何一次复盘，优先砍范围，不砍"先发布"这个目标**。
